# English Coach

A small local web app for practising spoken English (and Russian): record
yourself, get a **faithful, verbatim transcript**, then ask Claude for
structured feedback — grammar mistakes, word order, fluency issues and more,
explained in Russian and tagged by topic so the app can track what you keep
getting wrong across sessions.

The app runs entirely on your own PC. A small Python backend serves a page in
your browser; nothing is hosted, nothing needs an account beyond your own
Deepgram and Anthropic API keys.

The transcript itself is never touched:

* no grammar correction, no rephrasing, no style improvement
* no removal of repeats, fillers or unfinished sentences
* `smart_format` is off on purpose — `punctuate=true` gives sentence
  punctuation without reformatting the words

Transcription is done by **Deepgram Nova-3** in the cloud. Feedback is
generated by **Claude (Sonnet 5)**, only when you press "Analyze" — it never
runs automatically, so you always know when an API call (and a few cents of
spend) is happening.

## 1. Quick start

### 1.1 Get your API keys

1. **Deepgram** (transcription): sign up at
   <https://console.deepgram.com/signup> (new accounts get free credit), then
   **API Keys → Create a New API Key**.
2. **Anthropic** (feedback): create a key at
   <https://console.anthropic.com/> under **API Keys**.

### 1.2 Create your `.env`

Copy `.env.example` to `.env` in the project folder and paste both keys:

```
DEEPGRAM_API_KEY=your_deepgram_api_key_here
ANTHROPIC_API_KEY=your_anthropic_api_key_here
```

`.env` is listed in `.gitignore` and never committed. You can instead set
real environment variables with the same names; a real environment variable
always takes priority over `.env`.

### 1.3 Install Python dependencies

Requires Python 3.10+ (3.12 recommended).

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 1.4 Run the app

```bat
run.bat
```

or by hand:

```bat
python -m app.main
```

This starts a local web server and opens your browser at
`http://127.0.0.1:8420`. Leave the console window open — closing it (or
pressing Ctrl+C in it) stops the server. Override the host/port with the
`APP_HOST`/`APP_PORT` environment variables if 8420 is taken.

**Important:** always reach the app through that `http://127.0.0.1:...` URL,
never by double-clicking `app/static/index.html` directly — the browser only
grants microphone access on a proper server origin.

### 1.5 Record, transcribe, get feedback

1. On the **Запись** (Record) tab, pick your microphone and the language you
   are practicing, then press **Начать запись**. Your browser will ask for
   microphone permission the first time.
2. Speak for as long as you like, then press **Остановить**.
3. The recording uploads automatically and is transcribed by Deepgram — you
   will see the verbatim transcript once it's done.
4. Press **Анализировать (Claude)** to get coach-style feedback in Russian:
   each mistake quoted from your own words, explained and corrected, with
   simpler/more natural alternatives, plus an improved version of the whole
   monologue, key phrases to remember and scores (see section 3).
5. Visit **История** (History) to revisit any past session, and **Прогресс**
   (Progress) to see which topics keep coming up across all your sessions.

Listening is practised the other way round, on the **Диктант** activity
(«Занятия» → Диктант): paste a YouTube link, and the video is imported as a
lesson — its audio plus the sentences of its own subtitle track. You then type
each sentence word by word while the player repeats it (Enter listens again,
Space moves to the next word, Tab reveals the current one). This activity is
free: it needs neither Deepgram nor Claude, only `yt-dlp`, and a video without
usable subtitles is refused rather than transcribed.

### 1.6 What's saved on disk

```
recordings/2026-09-13_18-40-05/
    audio.webm               (your original recording, browser-encoded)
    session.json             (session status/metadata)
    transcript.txt           (the verbatim transcript)
    deepgram_response.json   (full raw Deepgram API response)
    analysis.json            (Claude's structured feedback, once you Analyze)
data/
    progress.json            (aggregated topic frequency across all sessions)
data/dictation/<video id>/
    lesson.json              (the video and its sentences, with timings)
    audio.m4a                (the audio exactly as YouTube served it)
    subtitles.vtt            (the caption track the sentences came from)
    results.jsonl            (every dictated sentence — append-only)
```

Everything after the `---` in `transcript.txt` is exactly the string Deepgram
returned, written in UTF-8, untouched.

## 2. Language

The language dropdown on the Record tab picks what gets sent to Deepgram:

| Choice | Request | Filler words |
| --- | --- | --- |
| `English (US)` | `model=nova-3&language=en-US` | **yes** (`filler_words=true`) |
| `Русский (Russian)` | `model=nova-3&language=ru` | no |
| `Mixed speech (RU + EN)` | `model=nova-3&language=multi` | no |

Deepgram documents `filler_words` as an **English-only** feature — Nova-3
transcribes Russian well, but hesitations like `э-э`, `мм`, `ну` are not
specially preserved the way `uh` / `um` are in English. Everything else is
identical for all three choices: `punctuate=true`, `smart_format=false`, no
rewriting.

Claude's feedback is **always written in Russian**, regardless of which
language you practiced — you get Russian explanations whether the mistakes
were in English or Russian speech.

Set `DEEPGRAM_LANGUAGE=ru` in `.env` to start the app with Russian selected
by default.

## 3. Feedback and progress tracking

Pressing **Analyze** sends the transcript to Claude (`claude-sonnet-5` by
default) with structured output, asking for:

* a short Russian-language summary of the recording and what went well
* a walk-through of specific issues in transcript order, each with: the exact
  quote from your transcript, a Russian explanation, a minimal correction,
  simpler / more natural ways to say it, the reusable construction behind the
  fix (e.g. `help someone + verb`) with examples, a severity (minor /
  moderate / major), and a **topic** from a fixed list (verb tense, articles,
  word order, prepositions, agreement, word choice, sentence structure, filler
  words, repetitions, naturalness, other)
* words you were searching for or confused (e.g. employee / employer / recruiter)
* the whole monologue retold the way it could have sounded — shown next to
  your transcript, which itself is never changed
* 3–5 constructions to remember from this recording
* scores from 1 to 10 for grammar, vocabulary, fluency and naturalness, plus
  an overall average

Every analyzed session's topics feed into `data/progress.json`, a running
tally of which topics come up most often and most recently. The **Прогресс**
tab ranks your weakest topics from that file. From there, each topic links to
a **Practice** screen — for now those are placeholders ("coming soon"): the
grammar-quiz / translation / spoken-practice exercise types are not built
yet, only the navigation shell is.

Analysis is **on-demand only** — pressing the button again on an already-
analyzed session reuses the cached `analysis.json` unless you force a
re-run, so accidental double-clicks never cost you a second API call.

Estimated cost: roughly $0.05–0.10 per analyzed session with Sonnet 5 — a few
dollars a month even with daily practice. Change the model in
`app/config.py` (`ANALYSIS_MODEL`) or tune quality/cost with the
`ANALYSIS_EFFORT` environment variable (`low`/`medium`/`high`/`xhigh`/`max`)
if you want to trade cost for depth.

## 4. Audio format, and why

Recording happens in your browser via `MediaRecorder`, typically producing
`audio/webm;codecs=opus` (Chromium/Edge) or `audio/ogg;codecs=opus`
(Firefox). Deepgram auto-detects the container from the bytes, so no
conversion happens on the way in — whatever your browser records is exactly
what gets uploaded and transcribed.

Recording duration is measured in the browser (a simple timer) rather than
parsed from the audio file server-side, since that only works cleanly for
WAV and this app deliberately avoids adding an audio-decoding dependency.

The original audio file is never deleted, including after a successful
transcription and analysis.

## 5. Error handling

| Situation | What happens |
| --- | --- |
| `DEEPGRAM_API_KEY` missing | The recording still uploads and saves; the session is marked as an error with a clear message instead of being sent to Deepgram. |
| `ANTHROPIC_API_KEY` missing | The transcript still works; pressing Analyze returns a clear "not configured" message instead of failing silently. |
| Wrong / revoked API key (either service) | Reported in plain language (Russian, for Claude; English, for Deepgram, matching each service's own error surface). |
| Claude rate limit / timeout / refusal | Reported with a retry-friendly message; the transcript and any earlier analysis are never lost. |
| No internet | Clear message; the recording/transcript already on disk is untouched, and you can retry from the History view. |
| No microphone / permission denied | The browser reports this directly; press Refresh in the mic dropdown after fixing it. |
| Empty recording (too short) | Reported instead of being uploaded to Deepgram. |

## 6. Logging

`logs/app.log` (rotating, 1 MB × 4) records: app start, upload/transcription
start and result, analysis start and result, and any errors. **API keys are
never logged** — only whether each one is configured. uvicorn's own request
log also goes to the console.

```
app/
    __init__.py
    main.py             entry point: starts uvicorn, opens the browser; --selftest
    server.py           FastAPI app factory (mounts /api + the static frontend)
    api.py              all /api/* routes

    utils.py            Session model, transcript formatting, filesystem helpers

    progress_store.py    cross-session topic aggregation (data/progress.json)
    exercise_sets.py     Claude layer: AI exercise sets (generation + grading)
    speech_drills.py     spoken-drill measurements from Deepgram word timings

    dictation_store.py   dictation lessons on disk (data/dictation/)

    learner_store.py     the learner model on disk (bank, attempts, usage)
    static/               the browser frontend (plain HTML/CSS/JS, no build step)
        index.html, css/app.css

        js/recorder.js (microphone capture, shared by every spoken activity)
        js/views/{today,practice,record,speech,dictation,history,session,progress}.js
tests/
    test_app.py           transcriber + session/file-layout tests
    test_analyzer.py       Claude integration tests (fake client, no network)
    test_progress_store.py topic-aggregation tests
    test_api.py            FastAPI route tests (fake transcriber/analyzer/YouTube)
    test_learner_*.py      learner model: rules and files
    test_exercise_sets.py  AI exercise sets (fake client)
    test_speech_drills.py  pace/filler/pause metrics, reading alignment
    test_dictation*.py     subtitle parsing, grading, lesson files

```

**Packaging note:** this app used to ship as a PyInstaller `.exe`. A
persistent local web server doesn't map cleanly onto that onefile/windowed
build, so packaging is deferred for now — run it from a Python checkout via
`run.bat`.

## 8. Tests

```bat
python -m unittest discover -s tests -v
```

No microphone, no browser, no network, and no real API keys are needed.
Deepgram and Claude are both exercised through fake/mock clients, including a
contract test that drives the **real** Deepgram SDK through an `httpx` mock
transport to assert the exact HTTP request it builds.

`python -m app.main --selftest` runs an equivalent smoke check on a source
checkout (or a future packaged build): it exercises the Deepgram and Claude
request paths against fake clients and makes sure the FastAPI app builds,
without starting a server, opening a browser, or touching the network.
